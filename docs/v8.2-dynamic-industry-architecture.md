# V8.2 Dynamic Industry Workspace

本阶段采用渐进迁移，不重写现有页面。HTML 结构、CSS class、动画参数、ECharts option 和旧全局入口继续保持兼容。

## Runtime layers

1. `AppStore` 是当前数据的唯一 source of truth；`DATA` 和 `DASHBOARD_DATA` 仅为兼容别名。
2. `IndustryStore` 统一解析和保存 `industryId`；界面名称只用于展示。
3. `StorageAdapter` 是 localStorage 的唯一访问层，负责 JSON 容错、自定义行业配置、数据和行业列表。
4. `DataPipeline` 负责 normalize、validate 和 prepare，渲染层只消费准备完成的数据。
5. `AppLifecycle` 负责 prepare、render、ready 和统一 destroy。
6. `ChartManager` 负责 ECharts create、update、resize、dispose 和 disposeAll。
7. `EffectsManager` 管理页面 effect cleanup；`EventManager` 管理可销毁事件；`TimerManager` 管理全部 timeout 和 interval。

## Industry lifecycle

```text
switchIndustryContext(industryId)
  -> invalidate requestId
  -> EffectsManager.destroyPage()
  -> ChartManager.disposeAll()
  -> EventManager.clear()
  -> TimerManager.clearAll()
  -> IndustryStore.setCurrent(industryId)
  -> navigate to the industry URL
  -> load industry config and raw data
  -> AppLifecycle.prepare(data)
  -> renderAll()
  -> init effects
```

异步采集继续使用 `requestId` 隔离。旧请求完成后必须通过 `AppStore.isCurrent(requestId)` 才能更新 UI 或存储。

## Legacy compatibility

- `window.DATA`、`window.DASHBOARD_DATA`、`window.NS`、`window.renderAll`、`window.switchIndustryContext` 保留。
- 旧模块仍可调用 `echarts.init`，全局安全代理会转交统一注册表；已迁移模块直接使用 `ChartManager`。
- 原有动画、hover、滚动效果和按钮反馈不改变参数，只把资源登记到对应 Manager。
- `app.html` 继续保留现有 DOM，后续拆分必须逐块迁移并维持视觉截图基线。
